# Approved production plan

1. Architecture: Node24, pinned Apify SDK, ordinary first-party HTTPS, complete archive integrity verification, streaming JSON normalization and a bounded temporary SQLite index.
2. Inputs: optional game-or-hardware filter and maxResults, default10. Launch cap1000 after measured276–292second large runs;10000is projection-only.
3. Output: one original written report per row with content ID, Steam ID/title, player date/verdict, complete notes, supplied GPU/OS/driver/Proton fields, source/archive links, snapshot label, collectedAt and license attribution.
4. Collection: resolve latest dated maintainer file from archive index, download and verify its Git blob hash, scan all records, retain newest matching usable distinct reports. There are no hundreds of detail URLs or website pagination.
5. Errors: reject bad inputs; bounded transient retries respecting rate limits; fail on access denial, corrupt/truncated archives or integrity mismatch. No substitute data. Persist native manifest and reconcile dataset/outbox on same-run resume.
6. Tests: local schema/identity/legacy/error/recovery tests; progressive cloud10/100/500/1000; repeat, game, empty, low-budget and native idempotency replay. Independently compare identities/content to verified source evidence. Record every run/build and all resource/event counts.
7. Performance: initial1024MB with512MB considered only if sufficient headroom; default must finish below300seconds. Source file scans are required for newest-first ordering. Preserve global Manager caps and keep total discretionary native build/test spend belowUSD10.
8. Monetization: approved start fee plus full written reports. Saved prices: USD0.05 once-per-export preparation and USD0.0005/report, platform usage included under standard PPE. Custom preparation and report charges reconcile native cumulative event counts on resurrection; automatic startup and dataset-item charges are disabled. No tier discounts until justified. Verify margins and empty/low-limit behavior before publication.
9. Deployment: public GitHub source and private limited-permission Actor; inspect builds and tests, complete ODbL/DbCL attribution and public transformation code, save Manager readiness evidence, publish only after gates, then verify Store/pricing/default production run. No recurring Tasks/schedules or unrelated Actor changes.
